# A/B/C/D 独立实验代码

四组实验共享相同的时间口径和27个输出，每组拥有独立目录、字段契约、调参、扩大样本确认和最终训练脚本。窗口校验统一复用本目录的 `window_contract.py`。

历史A/B/C/D现在默认使用仓库内 `crossformer/` 主干，不再导入外部 `Time-Series-Library`。兼容参数 `--library-root` 已可省略；即使提供该参数也不会加载外部代码。需要保持完整仓库结构。

在仓库根目录安装历史实验依赖（包含调参必需的Optuna）：

```bash
python -m pip install -r experiments/latency_abcd_27/requirements.txt
python experiments/latency_abcd_27/A_128_history_to_27/tune.py --help
```

新主干保留原模型的参数名称与结构，并以原发布权重验证严格加载及前向输出；历史模型训练仍要求CUDA。首次使用还需要提供已重建为10秒空档的训练数据。上述历史方案输出27字段；需要统一原128输出和G1–G4时，应使用 `input_window_matrix_v1` 的同名输入方案。新独立导出流程支持matrix/ALL90模型，不将旧27输出模型冒充原128输出模型。

三个留一设备确认折上 C 均略优于 D，因此 C 是当前主实验结果。D 在设备 04 上的微小优势不能证明“设风速”具有跨设备增益：该字段在现有数据中可能代理设备身份，而且 27 个输出的历史筛选曾参考设备 04。

最终训练按设备平衡到最小设备的窗口数，设备 01/02/03 各使用 73,050 个窗口，共 219,150 个；这不是把设备 02/03 的所有额外窗口都纳入训练。

## 统一实验顺序

1. 对 A/C 使用现有 133 字段数据根目录执行只读契约检查；D 先构造独立 134 字段数据集，再做相同检查。
2. 每组独立执行 `tune.py`。默认 8 个 trial、每折最多 3000/1500 个训练/验证窗口、每个 trial 最多 5 个 epoch。
3. 用该组的 `best_trial.json` 执行 `confirm.py`。默认扩大到每折 12000/6000 个窗口、最多 8 个 epoch。
4. 只有确认结果通过后才执行 `train_final.py`，使用设备 01/02/03 和确认阶段最佳轮数的中位数训练最终模型。

A/C/D 的调参目标完全一致：22 个连续量相对持久性基线的 MSE 与 5 个布尔量宏 F1 组成目标，三折汇总为 `0.75 × 折均值 + 0.25 × 最差折`。设备 04 不进入调参或确认。D 的“设风速”受设备混杂限制，结果必须与 C 成对比较，并同时查看三个留一设备折，不能只报告聚合均值。

# 全量 90 新特征的 Crossformer 质量与推理时间比较

状态：方案和独立代码已编写；本次不启动模型训练。第三组按用户补充确定为 180s + 10s + 120s。

2026-09-29 更新：新增第四组 300s + 10s + 60s，形成历史长度（180/300 秒）与输出长度（60/120 秒）的完整 2×2 比较。

## 1. 实验目标与四组窗口

业务输入固定为旧 128 个字段 + 新增 90 个字段，共 218 个不同的源字段；输出严格沿用已发布 manifest 中旧 128 个字段的名称、顺序和类型（56 连续、72 布尔）。四组都使用全部 90 个新增字段，不再沿用旧实验的字段筛选。

|组|名义历史|空档|预测区间长度|历史/跳过/输出点数|相对最后历史点的标签时间|
|---|---:|---:|---:|---|---|
|G1|300 秒|10 秒|120 秒|150 / 5 / 60|+12、+14、…、+130 秒|
|G2|180 秒|10 秒|60 秒|90 / 5 / 30|+12、+14、…、+70 秒|
|G3|180 秒|10 秒|120 秒|90 / 5 / 60|+12、+14、…、+130 秒|
|G4|300 秒|10 秒|60 秒|150 / 5 / 30|+12、+14、…、+70 秒|

采样周期为 2 秒。沿用项目的“空档 = 跳过采样点”定义：+2/+4/+6/+8/+10 秒共 5 点不作为标签，首个标签在 +12 秒。150 个历史采样点首末相隔 298 秒，仍按项目惯例称 300 秒历史；90 点同理。这里的 10 秒空档是预测任务定义，与模型计算耗时分开记录。

固定输出长度比较历史长度：G1/G3 对应 120 秒输出，G4/G2 对应 60 秒输出。固定历史长度比较输出长度：G1/G4 对应 300 秒输入，G3/G2 对应 180 秒输入。四组均比较共同前 60 秒质量及配对推理耗时。

## 2. 90 字段的来源和逐字段契约

字段名单直接从 `docs/PLC_NEW90_TO_128_EXPERIMENT_PLAN.html` 内嵌的 `queries.fields.rows` 读取，共 90 条，并与新增 Parquet schema 对照。旧字段顺序来自 `LightX_Crossformer_Time_forscasting/artifacts/feature_manifest.json`。

`experiments/all90_latency_v1/contract.json` 保存完整 218 字段顺序、90 条逐字段编码说明、四组窗口、固定训练预算和来源 SHA-256；`build_contract.py` 可以从上述源文档重新生成。旧方案中“常量不入模”“测试记录排除”等决定是历史上下文，本次按用户的新要求改为全部保留，并使用下面的编码规则。

Git 分支包含 `experiments/all90_latency_v1/sources/added_fields.json` 精简来源副本，仅保留字段名称及历史分层、注意事项。独立克隆时由该清单和仓库根目录的 `artifacts/feature_manifest.json` 重建相同契约，无需原工作区 HTML；原始来源哈希保持不变。运行真实数据流程仍需另行提供数据目录。

|字段种类|处理方式|进入模型的方式|
|---|---|---|
|打印层数、CSV 铺粉器速度|训练侧标准化；与旧同名/近义测量保留独立来源|进入 Crossformer 动态分支，也在条件分支保留绝对历史值|
|普通设定值、时长、位置、扭矩等|仅用训练任务拟合尺度，不猜测 S/D 的物理含义，不与不明单位的旧量作差|全部进入条件历史分支|
|训练范围内常量|保留字段；中心为 0，尺度为 max(abs(训练常量),1)，不因零方差删除|保留绝对水平；无法保证常量会提供可识别增益|
|设铺粉模式、正/负压测试结果|按训练侧词表编码；缺失和未知类别独立编号；未知类别用中性 embedding|类别 embedding + 字段有效掩码|
|正/负压测试日期|北京时间解析；转换为在该历史快照时点已经过去的天数，再取 log1p|2 个日期各保留一个明确对应的编码字段|
|平台到位等缺失字段|未知值输入中性 0，同时设置该字段掩码为 0|避免把“未知”误当作 PLC 实际 0；不删掉相关任务|
|异名重复源 CSV 铺粉器速度|与旧 `铺粉器速度(mm/s)` 分开保留|不覆盖、不合并、不静默删除|

两项测试结果只有在其对应测试日期有效、且不晚于该行的历史源时间时才能使用；否则结果和日期一起标记未知。不会从后续行、任务结尾或未来设定回填历史。前提是 CSV 行确实是该时刻记录的快照；当前缺少实际上传到达时间和更细的结果可用性审计，这一点会写入数据元信息。

## 3. 模型结构

采用统一的 Crossformer + 条件历史分支，四组只有历史/输出长度不同：

```text
218 个有序业务字段
  ├─旧 128 + 打印层数 + CSV 铺粉器速度（130 动态通道）
  │   └─Crossformer + RevIN + 最后值残差 → 取旧 128 输出
  └─全部 90 新字段的绝对历史编码
      + 每字段有效掩码（90）
      + 旧源观测/新源观测/新源年龄（3）
      └─条件 GRU → 128 通道的预测修正
最终输出 = Crossformer 输出 + 可学习门控 × 条件修正
```

90 个原始字段各有独立的值位置和有效掩码。类别 embedding 和质量通道是编码展开，不计作额外业务字段。动态分支有 2 个新字段的重复表示，用于同时保留波形与绝对工艺水平；业务源字段的去重总数仍严格为 218。

固定初始参数：d_model=128、n_heads=2、e_layers=3、d_ff=512、seg_len=10、factor=3、dropout=0.05、条件 hidden=64、batch_size=32、AdamW lr=1e-4、weight_decay=1e-5。四组从头初始化，不装载 Epoch45 权重。预测头随输出长度变化，实际参数量也随之变化，训练结果会记录该数量。

损失：0.6 × 连续目标平均 Huber + 0.4 × 布尔目标平均 Huber，delta=1。条件字段不是预测目标。主比较使用 FP32；FP16 可作为单独记录的补充配置，不能混合汇总两种精度。

## 4. 数据、因果对齐与公平比较

旧 128 字段使用已有未裁剪的预处理 Parquet，新增 90 字段使用原始 `_added` 宽表；不使用旧 7 字段、133 字段或 U40 数据矩阵替代全量 90 字段。

以设备和任务确定范围，新源时间向上对齐到 2 秒 UTC 网格，只能延后可见、不能提前。相同网格冲突取源时间/源行号更晚的快照。最多因果保持 1 个缺失网格点，显式空值不被前值覆盖；长缺口、旧段、新段、任务和设备均是硬边界。

旧数据中的线性插值行先撤销，再按旧 segment 最多因果保持 1 点作为输入。输出标签全部要求旧源 `observed_mask=True`；沿用旧布尔状态保持语义，不宣称每个状态都是该时刻的一次新硬件读取。原始真实物理量不按训练百分位裁剪。

设备 01 原有的三个旧源缺口任务继续排除。任何新增字段缺失都通过掩码表示，不要求 90 字段全部非空。因此不会因为设备 04 的“平台到位”全缺失而把设备 04 全部删掉。

四组主实验使用同一任务集合和同一预测起点集合：先以最长历史和最长输出构造共同合格起点，再为每组切取自己的历史和输出。默认起点步长 5 点，即 10 秒。训练窗口按设备最小可用窗口数等量采样，四组同种子的采样一致；验证和 04 使用自然分布的全部共同窗口。较短窗口原本可能多出一些可用任务或起点，这些额外样本不进入本次主比较，以保证可比性。数据 manifest 保存各任务行数、共同窗口数、剔除原因、源与产物哈希。

完整构造按任务分片，不一次性把全四设备 218 通道装入内存。每任务保存 values.npy、rows.parquet、origins.npy，运行时 mmap 读取。

## 5. 训练与模型选择

设备 01/02/03 各自按任务开始时间排序，末尾 20% 的完整任务作为内部验证；其余任务用于选择阶段训练。任务不跨 split，scaler/类别词表/活跃目标集合只在对应训练任务上拟合。

四组使用相同的 3 个随机种子、固定结构参数和训练预算；最多 50 epoch，patience=8。首轮不为某组额外调参，以便观察窗口长度的影响。每组每种子选内部验证最优 epoch；该组的最终轮数取三个最佳轮数的中位数。随后用 01/02/03 全部合格任务重新拟合预处理器，各组各种子按固定轮数从头训练。

计划为 12 次选择训练 + 12 次最终训练，共 24 次独立训练；本次只交付代码，不执行这些命令。每次保存 model、optimizer、scheduler、AMP 状态、随机状态、完整训练历史和数据/代码身份，续跑要求预算及契约完全一致。

04 不用于梯度、scaler、类别词表、早停或 epoch 选择。业务要求的 04 质量和速度比较在全部最终模型完成后独立执行，报告全部三个种子，不能在 04 上挑一个“最佳种子”。由于历史项目已查看过 04，将其标记为探索性业务评估；本轮比较后若据此选部署方案，不能再把 04 称为未用于选择的确认集。

## 6. 预测质量

主比较包括各组自身完整区间和四组共同的前 60 秒标签（+12…+70 秒）。G1/G3 还可直接比较完整 120 秒区间，G2/G4 的完整区间均为 60 秒。共同区间使用完全相同的预测起点和真实标签。质量比较输出 6 对共同区间比较，以及 G1/G3、G2/G4 两对相同输出长度的完整区间比较。

- 连续量：每字段原单位 MAE、RMSE、MSE、最后值基线、相对 MSE 与 skill；聚合相对误差按训练尺度标准化。
- 布尔量：F1、precision、recall、accuracy、误报率、正例数及预测区间内部状态切换指标；0.5 阈值反归一化后使用。活跃字段集合在训练侧冻结，常量字段仍保留在逐字段报告。
- 统一内部选择指标：J = 0.7 × 活跃连续量标准化 MSE / 持久性对应 MSE + 0.3 × (1 − 活跃布尔 macro F1)。基线分母为零时返回不可评分，不用任意 epsilon 制造数值。
- 每任务、每 30 秒预测时距分层、三种子均值/标准差；任务级配对 bootstrap 95% 区间。先在同任务内平均配对种子的差，再重采样完整任务，不把高度重叠的窗口当独立实验。

任务等权 bootstrap 的 J 差与全部点加权的总体 J 是不同口径，输出分别标明。

## 7. 推理时间

04 的同一批共同窗口用于计时。默认每模型 50 次预热，按任务均衡选取 256 个覆盖时间范围的起点，重复 3 轮。每模型约 768 个请求；每个请求 batch=1，模型 eval + inference_mode，不计算梯度。

测量两种范围：

1. **前向耗时**：输入已经编码并位于目标 CPU/GPU，测同步后的模型前向墙钟耗时。
2. **模型服务流程耗时**：从内存中已对齐、已完成类型解码的 218 字段窗口开始，包含标准化、类别与掩码编码、Tensor 构造、设备传输、前向、拷回 CPU、反归一化、布尔阈值。

两者均不包含磁盘/网络/采集等待、跨源融合、原始日期字符串解析、加载权重或任务定义中的 10 秒空档。因此第二项不是传感器到业务 UI 的总延迟；真实端到端耗时需要在线采集和服务部署后补测。

CUDA 计时在每次请求前后同步，避免只测到异步提交。随机交错所有组与种子的执行顺序，前向/服务两种范围的先后次序也随机化。使用同一个进程、硬件、线程数、精度和 eager 执行模式；CPU 默认单线程，可显式更改并记录。FP32 关闭 TF32。GPU 上若发现其他计算进程，默认要求在空闲时重新计时；显式允许竞争时会在报告标注。

每模型和每组记录平均、标准差、P50/P90/P95/P99、最小/最大值，保存逐请求耗时；按相同任务/起点/种子/轮次计算配对差和任务级区间。环境记录 CPU/GPU、内存、Python/PyTorch/CUDA/cuDNN、线程数、模型参数量和 checkpoint SHA。CPU 与 GPU、不同精度或硬件的结果各自保存在独立目录。

最后生成质量与延迟并列表，展示共同 60 秒质量和服务 P95 耗时的 Pareto 关系，不把两个单位不同的指标任意相加。业务尚未提供延迟 SLA 或允许的质量退化阈值，代码展示权衡，不自动宣称某组满足上线标准。
